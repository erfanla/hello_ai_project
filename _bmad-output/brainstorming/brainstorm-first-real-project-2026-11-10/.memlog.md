- (idea by user) Core idea: app/web page where you post an activity invite (e.g. 'anyone want a burger, here are the details') and friends just answer yes or no, no group-chat discussion

- (idea by user) Fun status feature: 'today I'm in the mood', 'this week I'm short on money', so friends know without an awkward talk
- (idea by user) When friends see a 'low money' status, they suggest free activities (e.g. dinner at someone's house, share food)

- (question by user) Not sure if money/status features are a good idea (shame or awkwardness risk?)

- (question by user) How does the inviter feel when everyone says no? Not sure yet

- (decision by coach) Proposed stack: web app first as installable PWA (works on phone, web push); Python FastAPI backend; SQLite then PostgreSQL; simple frontend with server HTML + HTMX (React later); host on Render/Railway/Fly.io; AI features via an LLM API in a later version
- (decision by user) Agreed: Python + FastAPI for the backend
- (question by user) What are the pros and cons of the database and frontend choices? Are there better options?
- (insight by coach) DB note: SQLite on free hosting may lose data on redeploy; plan: SQLite locally with an ORM (SQLModel), managed PostgreSQL (Neon or Supabase) when deploying. Supabase also gives login + photo storage. NoSQL (Firebase/Mongo) fits worse because data is relational
- (insight by coach) Frontend options: HTMX (mostly Python, fast, less job demand), React (most job demand, but JS + 2 projects + slower start), Python-only UIs like Streamlit (not good for a mobile consumer app), Flutter/React Native (real mobile, new language, later)
- (decision by user) Agreed: HTMX (server HTML) frontend for v1
- (question by user) If photo sharing is in the first version, can we still use SQLite?
- (insight by coach) Photos are not stored in the database: files go to storage (local folder in dev, object storage like Supabase Storage / Cloudflare R2 / S3 in production); DB only keeps the file path/URL. SQLite is fine for that. Photos add work: upload, resize, privacy (only invite members can see)
- (decision by user) Photo album stays in 'Could' (later), not in v1. Final v1 stack: PWA web app, Python + FastAPI, HTMX, SQLModel with SQLite locally -> PostgreSQL (Neon/Supabase) at deploy
- (insight by user) Heart of the app: it helps introverts, and helps avoid conflicts between friends
- (insight by coach) Synthesis: core principle is 'nobody loses face'. Silent no, invisible invites, answer visibility, busy-tonight cover, soft result screen, anonymous gift, mutual crush are one idea in many forms: protect feelings.
